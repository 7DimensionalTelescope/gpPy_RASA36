# RASA36 Pipeline — CLAUDE.md

Guidance for working on the RASA36 CCD reduction pipeline. Read the root `/data3/youngpyo/CLAUDE.md` first (paths, envs, shared-server rules).

## Running

Always in the **`rasa`** conda env:

```bash
conda run -n rasa python IMSNG_Routine_RASA36.py <input_folder> [ncores] [--no-stack]
# example:
conda run -n rasa python IMSNG_Routine_RASA36.py /data6/obsdata/RASA36/image/2026-06-22_gain25 4
```

- `<input_folder>` — an explicit date folder (`/data6/obsdata/RASA36/image/<YYYY-MM-DD>_gain25[_ToO]`) or a staging dir
- `ncores` — default 4; do not raise unprompted (shared server)
- `--no-stack` — each frame becomes its own "stack group" (used for ToO / GRB time-series photometry where per-frame epochs matter)
- `--stack-sec <sec>` — cap each stack group at `<sec>` total EXPTIME (e.g. `--stack-sec 300` builds 300-s epochs from 100-s frames). The 1-hour time-gap grouping still applies first; each gap group is then chunked in time order (`_split_group_by_exptime`). Only the stack stage is chunked — SCAMP Pass A still uses the full gap groups. Ignored with `--no-stack`. Added 2026-07-10 for GRB260421B 300-s epochs.
- Batch re-runs: edit the `FOLDERS` array in `rerun_failed.sh` (runs sequentially — all runs share the factory dir)
- Syntax check after edits: `conda run -n rasa python -m py_compile IMSNG_Routine_RASA36.py` (and `preprocess/calib.py` etc. if touched)
- **Never launch a full run just to verify a code change** — runs take hours and are memory-heavy.

## Stage sequence

```
header correction → master frames (bias/dark/flat) → object calibration →
astrometry (solve-field) → rename → SCAMP/MissFITS WCS refinement → photometry →
image stack (SWarp) → photometry (combined) → subtraction (hotpants) →
photometry (subtracted) → transient search → summary → file transfer
```

`CHANGELOG_pipeline.md` documents how this differs from the original gpPy version (multiprocessing, logging, RASA36-hardcoded).

**Slack step numbering / time accounting (2026-07-16):** the thread posts numbered
`[n/10]` step messages, each `— Ns` being that stage's own `protbl` time, so consecutive
messages' `Ns` sum to the wall clock. The **SCAMP + MissFITS WCS-refinement** block
(`protbl` process `wcs_refine`) is now its own step `[4/10]` — it used to record no
`protbl` time and post no Slack message, so its wall-clock (~45% of a nightly run — see
`scamp-stage-speed-profile`; 625 s even on a 10-frame ToO) vanished into the gap between
`[3/10] Astrometry` and photometry, making the photometry step's reported time look far
shorter than the elapsed time since astrometry. Full order:
`[1] master → [2] pre-process → [3] astrometry → [4] wcs_refine → [5] photometry →
[6] stacking → [7] photometry(combined) → [8] subtraction → [9] photometry(subtracted) →
[10] transient search`. Remaining untracked slivers are sub-2 s (header correction before
the `st` timer at ~line 763; the rename-to-IMSNG block before SCAMP) — negligible vs the
former 625 s hole. If you add a stage, give it a `protbl` process row **and** a Slack step,
and bump `/10`, or its time disappears from both the summary and the thread.

## Subtraction references (two-tier)

`_resolve_refim(obj, filte, sci_center=None)` (shared since 2026-07-13 by `_subtract_one` **and** the
transient-search block — previously transient search read the legacy `factory/ref_frames/` dir and
crashed with `list index out of range` for any TOS/pre-staged template) picks the template for a tile
in this order:
1. **Prior TOS epoch** — earliest `path_result/TOS/<obj>/*/<filter>/Calib*.com.fits` of the
   same tile, excluding the current date (self-reference).
2. **Pre-staged external template** — if no prior epoch exists, fall back to
   `path_refimg/Ref-RASA36-<obj>-<filter>-<survey>.fits` (`path_refimg =
   /data6/obsdata/RASA36/reference_img`), the DESI/SkyMapper r-band templates built by
   `RASA36/make_reference_tiles.py`. So a tile's **first** epoch can still be subtracted.
   `.wcsremap.fits` intermediates are excluded from the lookup. Only `Ref-*` matching the
   tile `OBJECT` + filter is used; unknown tiles (no template) log `NO reference image` and
   skip, as before. Pre-staged templates are run through `_prestaged_to_cd` first: it
   rewrites their PC+CDELT WCS as a CD matrix into the factory (Becker `wcsremap` misreads
   PC+CDELT as 3600″/px), which also keeps the `.wcsremap.fits` temp in the factory instead
   of `reference_img`.

   **WCS-overlap guard (2026-07-20):** both tiers match candidates by the `OBJECT` **string**
   only, which is wrong-sky for legacy off-grid nights (see the root `RASA36/CLAUDE.md` /
   `legacy-off-grid-quarantine`): a night whose `OBJECT=T#####` maps to a *different* position
   in the current `displaycenter_new` grid was paired with a survey template ~80° away →
   empty wcsremap overlap → **all-zero `hd`** + near-empty `phot_sub.cat` + junk candidates,
   silently (found on T00464: science Dec −20.4, template Dec −59.1, 83° apart). Callers now
   pass `sci_center` (the science coadd's WCS center via `_img_center`) and `_resolve_refim`
   drops any candidate whose center is >0.5° away (logged `SKIP reference … (wrong-sky /
   legacy tile?)`), falling through to the next tier / `NO reference image`. **Fail-open** when
   a center can't be computed (a real overlap is <~0.3°; the failure mode is tens of degrees),
   so a WCS read hiccup never regresses the normal path.

   **Quality caveat (best-effort only):** survey-template subtraction is a coarse fallback,
   not clean transient detection. Measured 2026-07-09 (DESI × RASA36): ~46% of stars leave
   >5σ dipole residuals, driven by RASA36 astrometry (1.7″ systematic + 0.85″
   position-dependent vs Gaia) and the deep-sharp-survey / 4.7″-seeing PSF mismatch — **not**
   fixable by hotpants flags. Treat first-epoch (PRESTAGED) difference images as needing
   heavy downstream vetting; prior-epoch (TOS, same-instrument) subtraction is far cleaner.
   As a guard, `phot/gregoryfind_bulk_mp_2021.py` caps snapshot stamps at `MAX_SNAPSHOTS=100`
   per epoch (top SNR; added 2026-07-13 after 72k survey-template candidates produced 430k
   stamp files in 10 h). `*.transients.cat` always keeps the full candidate list.

   **Transient-search gate (2026-07-13):** subtraction runs for every target, but the
   transient search only runs on ToO targets (always) and TOS tiles whose template was a
   prior TOS epoch (`REFSRC='TOS'`). TOS tiles subtracted against a survey template
   (`REFSRC='PRESTAGED'`) keep their `hd*` image but are skipped with a
   `Skip transient search (PRESTAGED template on TOS tile)` log line — first-epoch
   candidate lists were junk-dominated. `_subtract_one` stamps `REFIM` (template path) and
   `REFSRC` into the `hd*` header; the transient stage reads those and only falls back to
   `_resolve_refim` for hd images predating the stamping.

   **Per-tile reporting (2026-07-14):** both stages summarize outcomes per
   (tile, filter, reference) in the log and their Slack step messages — `[8/10]` lists
   `subtracted, ref [TOS|PRESTAGED] <template>` / `NOT subtracted - no reference image` /
   `FAILED (wcsremap/hotpants)` per tile (capped at 25 Slack lines, full list in the log);
   `[10/10]` shows `Searched: N/M (skipped: S, errors: E, gregoryfind failures: F)` and a
   `Transient candidates: C` total, plus per-tile `searched vs <template> — c candidates`
   lines (2026-07-15). The pipeline audits gregoryfind output after the run: gregoryfind
   writes a `.transients.cat` for every image it processes — including source-free ones
   (empty-catalog guard) — so a missing catalog is counted as a per-image gregoryfind
   failure (its traceback goes only to gregoryfind stdout, which reprocess/conda-run
   swallows). Candidate counts are `flag==False` rows. ToO targets are labeled `<NOTES name> (<tile>) <filter>` via
   `_target_label`. `_subtract_one` returns a 6-tuple record and its body is
   try/except-guarded (one bad frame no longer aborts the stage).
   For auditing astrometry, the stack step now propagates SCAMP's achieved RMS onto the
   coadd header (`ASTRRMS1/2` reference vs Gaia, `ASTIRMS1/2` internal — degrees; plus
   `ASTRMSAS` = reference RMS in arcsec, `NASTRMS` = N frames), median over the stacked
   frames. `ASTREF_CATALOG` is already `GAIA-EDR3`; the offset field is ~⅓ smooth
   (edge-increasing distortion, could be helped by a guarded `DISTORT_DEGREES` bump) and
   ~⅔ random. Any `DISTORT_DEGREES` change must keep the star-poor-field guard (see the
   giant-coadd row).

## Multiprocessing conventions (hardened 2026-07-14)

All pools use the **fork** context (`mp_fork` / `get_context('fork')`; Python 3.14 defaults to
forkserver, which re-imports the worker's main module — never use a bare `Pool()`). Rules:

- **Every pool result goes through `imap_collect`** (per-result stall timeout, 1800 s): the
  remaining pools are astrometry ×3 (via `_astrometry_star`), pre-SExtractor (via
  `_pre_sextractor_star`), stack, and subtraction. Never add a bare `pool.starmap`/`pool.map` —
  it has no timeout and re-raises the *first* worker exception, aborting the stage for every
  remaining frame.
- **Don't pool millisecond work**: two stages were pools whose per-task cost was pure metadata
  (a header read + a couple of `fits.setval`/`mv` calls), so a fork-inherited-lock wedge would
  cost `imap_collect`'s full 1800 s for a task worth milliseconds. Both serialized in-process
  2026-07-15, same reasoning as the dark/flat combine fix: the post-SCAMP RACENT/DECCENT/RAPOLY
  update (~40 ms/image, ~30 s/night; wedged live on 2026-07-11_gain25) and the "Rename to IMSNG"
  stage (`_fnamechange_star`, ~7 ms/image, ~1 s/night). `_fnamechange_star`/`_astrometry_star`/
  `_pre_sextractor_star` are still defined and used where they belong. Fork pools are only for
  stages whose per-task cost actually dwarfs the wedge risk (solve-field, SWarp/SCAMP, hotpants).
  Related corollary — **don't fork a pool for a single task**: the stack stage's per-group cost
  is large (SExtractor+SCAMP+MissFITS+SWarp), so it keeps its fork pool for multi-group nights,
  but when `len(all_stack_args) <= 1` it runs in-process (~line 1872) — a one-task fork pool has
  no parallelism to gain and only inherits the wedge risk (2026-07-16 fix; ToO/most GRB runs are
  single-group).
- **Wedged-worker abandonments surface in Slack**: `imap_collect` appends every stall to a
  module-level `POOL_ABANDONED` list `(stage_desc, n_abandoned)`; the final `Pipeline Complete`
  summary adds a `:warning: Abandoned N task(s) to wedged workers — <stage n>…` line when it's
  non-empty (2026-07-15 — a stall used to be log-only). The `[6/10] Stacking` message also now
  reports `Combined: n/N groups | Failed: F` (was bare `Combined: n`).
- **Per-task exception isolation everywhere**: the `_*_star` adapters, `phot_routine_safe`
  (gregoryphot), `routine_safe` (gregoryfind), and the guarded `_phot_sub_one` driver loop
  (gregoryphot_sub — sequential, one corrupt hd used to kill all later epochs) log/print the
  failure and return None so one bad frame never costs the batch. gregoryphot's
  `*.fail.list` is now real (failures returned to the parent; worker-side `failist.append`
  never survives the fork).
- **Thread budget = ncores (4), not cores×threads**: pooled workers set
  `OMP/OPENBLAS/MKL/NUMEXPR_NUM_THREADS=1` (calib astrometry fns were 4 → 16 threads/run);
  `config/rasa36.swarp` and `rasa36.scamp` use `NTHREADS 4` (was 0 = all 48 cores, ×4 workers
  ≈ 192 threads/run, ×2 with the ToO lane). Keep any new config at ≤4.
- **External children must be time-bounded**: hotpants (`timeout -k 30 900`), wcsremap
  (`timeout -k 30 600`), solve-field (`--cpulimit`). A pool abandon does NOT kill an
  `os.system` child — an unbounded one survives as an orphan burning a core.

## Companion processes

- **`rasa36_watcher.py`** — inotify watcher on `/data6/obsdata/RASA36/temp_tar/`: extracts incoming `.tar` files to `/data6/obsdata/RASA36/` and launches the pipeline once per tar (dedup via `log/rasa36_watcher_processed.txt`). Slack: one thread per tar in `#pipeline--imsng`. `MAX_TAR_FILES` controls tar cleanup (None = keep all; **setting it deletes oldest tars — data loss risk**). **Two pipeline lanes (2026-07-13):** tars whose stem ends in `_ToO` (case-insensitive) go to a dedicated fast lane running in parallel with the regular lane, so a ToO never waits behind a nightly reduction; jobs within a lane stay serialized. Both lanes use the same `--ncores` (default 4), so an overlap means 2×4 cores — memory watchdog should be running. **Skip-unpack (2026-07-13, size-verified since 2026-09-22):** if `image/<tar-stem>/` already exists with ≥1 FITS file, extraction is skipped and the pipeline runs on the existing dir — but only if `_extracted_dir_complete` confirms the on-disk byte total is ≥ the tar's own total file size; a mismatch (interrupted transfer, watcher restart mid-unpack, disk full) logs `looks incomplete` and re-extracts (tarfile.extractall overwrites in place, no manual dir deletion needed). Before 2026-09-22 the check was file-count-only, so a partial extraction could look "done" forever. **Stall alert (2026-07-14):** while a pipeline runs, the watcher checks the run's newest log (`log/RASA36/<input_folder>/*.log`) every 60 s and Slack-alerts once if it has been quiet >60 min (alert-only, never kills; re-arms when the log grows again) — added after the 2026-07-13 wedged-worker hang went unnoticed for 10 h. **Processed-state semantics (2026-07-14):** `log/rasa36_watcher_processed.txt` now means "pipeline run completed" (success or final failure), written by `_pipeline_worker` after `_run_pipeline` returns True — previously it was written at enqueue time (= extraction done), so a watcher restart silently dropped every extracted-but-not-yet-reduced tar from the startup backlog scan. Runs interrupted by watcher shutdown or skipped by the new `_same_folder_run_active` pgrep guard return False and stay unmarked, so they re-queue at the next start (extraction is then skipped via skip-unpack). **Ctrl+C = stop now (2026-07-14):** on SIGINT/SIGTERM the worker threads stop starting new runs — previously they drained the whole queue, launching a fresh multi-hour run per queued tar and requiring one Ctrl+C per job. The in-flight pipeline subprocess still dies with the terminal's SIGINT (same process group); it and every skipped queued tar stay unmarked and re-queue at the next watcher start.

**Two-stage shutdown (2026-09-22):** the first Ctrl+C/SIGTERM sets the shutdown flag *before* posting the "stopping" Slack message — previously the flag was set *after* `notify()` returned, so a second Ctrl+C arriving while that (blocking, network) call was still in flight passed the "already shutting down" guard and sent a duplicate "stopped" message; this was the actual bug behind repeated Ctrl+C spamming `#pipeline--imsng`, not a missing guard. A **second** Ctrl+C/SIGTERM (received after the flag is already set) now force-kills every subprocess in `_active_procs` (populated/cleared around each `Popen` in `_run_pipeline`) plus the memory watchdog, then `os._exit(1)` immediately — it no longer waits on `handler.stop()`'s thread `.join()`, which could hang forever if the in-flight pipeline subprocess was wedged past its first SIGINT or wasn't in the terminal's process group at all (nohup/tmux/systemd). This is the way to shut the watcher down entirely at once when the graceful path stalls. **One-time repair needed before the first restart with this code:** the live state file still lists the tars the old code marked at enqueue; keep only entries whose run actually started (log dir exists) or whose tar is gone: `cd toYP_pipeline && cp log/rasa36_watcher_processed.txt log/rasa36_watcher_processed.txt.bak && while read t; do s="${t%.tar}"; if [ -d "log/RASA36/$s" ] || [ ! -f "/data6/obsdata/RASA36/temp_tar/$t" ]; then echo "$t"; fi; done < log/rasa36_watcher_processed.txt.bak > log/rasa36_watcher_processed.txt` (run only while the watcher is stopped). Caveat: a run you killed mid-flight as part of the restart has a log dir, so the repair keeps it — delete that date's line manually so it re-queues.
- **`rasa36_reprocess.py`** (added 2026-07-14) — batch reprocessing: extracts any `temp_tar/*.tar` with no (or an empty) `image/<stem>/` dir, then runs the pipeline **strictly sequentially** (oldest first) on the selected `image/` folders. Shares the watcher's state file: after each completed run (success or failure) it appends `<folder>.tar` to `log/rasa36_watcher_processed.txt` so the watcher never re-runs that tar; interrupted runs stay unmarked. Safety: pidfile singleton (`log/rasa36_reprocess.pid`), refuses to start while `rasa36_watcher.py` is running (`--allow-watcher` overrides), per-folder `pgrep` same-folder guard, watcher-style stall alert (quiet log >60 min). Does **not** spawn `memory_watchdog.py` (removed 2026-07-15): reprocess runs strictly sequentially (one folder / 4 cores), well below the watcher's concurrent-lane footprint — start `memory_watchdog.py` yourself if you want monitoring during a sweep. Slack: one parent message in `#pipeline--imsng`, per-folder replies + final summary (`--no-slack` to silence). Selection: `--only/--exclude GLOB…`, `--start-from NAME` (resume), `--skip-processed`, `--extract-only`, `--no-extract`; always preview with `--dry-run`. If `--only`/`--start-from` matches zero folders (typo'd name), the run aborts immediately (before the pidfile, watchdog, or any Slack message) with a local log error only — added 2026-07-15 so a mistyped folder name doesn't post a spurious "0 folders" run to `#pipeline--imsng`. Run in the `rasa` env under nohup/tmux (a full 33-folder sweep is on the order of days — user must explicitly ask before launching; shared-server rules). Failures don't retry; the summary prints a ready-made `--only <failed…>` re-run command. Own log: `log/rasa36_reprocess.log`.
- **`memory_watchdog.py`** — polls system memory while the pipeline runs; Slack-alerts at CRITICAL only (<5% avail RAM, user-cgroup >90% of memory.high, or swap >20 GB with avail <50%; the WARNING tier was removed 2026-07-15 as noise). **Alert-only, never kills.** Pidfile singleton (`log/memory_watchdog.pid`); auto-spawned by the watcher.
- Slack credentials in `keys.dat`.

## Directory lifecycle

- **Factory** `/data3/youngpyo/RASA36/factory/RASA36/<input_folder>/` — working dir; the pipeline does `rm -rf` on its own factory subdir at run start and re-copies raw data. Failed runs leave partial files here; safe to delete factory contents, nothing else.
- **Output** `/data6/processed_RASA/`:
  - IMSNG galaxies → `IMSNGgalaxies/...`
  - non-ToO targets → `TOS/<obj>/<date>/<filter>/`
  - ToO → `ToO/<date>/<target>/<filter>/` (routing decided by `IS_TOO` header at run start)
  - **Inside each filter dir (layout since 2026-07-13):** stacked products (anything with
    `.com.` in the name, incl. `hd*`/`hc*` subtraction images and their `phot_sub` catalogs)
    stay at the top level; per-frame products (single-frame `.fits`, `.fits.back`, `.cat`,
    `.head`, `.png`, `.phot.*`, `.gcurve.*`, `.zpcal.png`, `.image.list`) go to `single/`;
    transient-search products (`.transients.` / `.new.` / `.ref.` / `.sub.`) go to
    `transients/` as before. Implemented via the `tails` move order in the File Transfer
    section (`'.com.'` tier before the `''` catch-all). Runs before 2026-07-13 are still
    flat — `cat_gppy.py` and `depth_test.py` use recursive globs and work with both layouts.
    **Single-frame `.head` = full merged header (2026-07-22):** SCAMP writes a WCS-only
    `.head` stub per frame in Pass A ([line 1459]), MissFITS merges it into the `.fits` but
    the stub persists, and photometry then reads it as SExtractor `HEADER_SUFFIX='.head'`.
    Just before File Transfer (after photometry — safe to overwrite by then) the pipeline
    re-dumps each single frame's **complete** merged FITS header to its `.head` via
    `header.totextfile()` (~line 2497, excludes `.com.*`), so the `single/` `.head` is now
    self-descriptive and consistent with the coadd `.com.head` (written at stack time,
    ~line 1821) instead of a 49-line SCAMP-only stub. Must stay after photometry — the
    stub is a live SCAMP→MissFITS→SExtractor exchange file during the run and overwriting
    it earlier breaks the WCS merge / photometry.
- Re-running a date simply overwrites outputs; wiping the target `T#####`/object subdirs first is recommended after several failed runs (partial files aren't cleaned up).

## ToO handling

A frame is treated as ToO when **any** of these hold (`_check_too`, ~line 492): `IS_TOO='True'`, `is_rapidToO='True'`, `OBJTYPE='Request'`, or `'too'` appears in the input-folder name or a raw filename. The target name comes from `NOTES` **or `NOTE`** (raw RASA36 ToO frames use the singular `NOTE`, e.g. `NOTE='M8'`; NOTES-fallback-to-NOTE added 2026-07-15 — without it a ToO tile fell back to its `OBJECT` tile name, e.g. routed to `ToO/<date>/T01974/` instead of `.../M8/`), and becomes the `NOTE` keyword in stacked images. Headers must be set **before** the run starts — `obj_meta` is built once at startup, so adding headers mid-run has no effect on routing.

**Concurrent runs (2026-07-13):** two pipeline instances on *different* input folders are safe (the watcher's ToO fast lane relies on this). Per-run isolation: own factory subdir, own log; shared master frames are written via `atomic_cp` (tmp + rename); SCAMP XML/check-plots and SWarp weight/XML outputs are redirected into the run's factory dir (`scamp_output_opts`) instead of the shared cwd. Same-folder concurrent runs remain forbidden (they'd wipe each other's factory subdir).

## Logs

`log/RASA36/RASA36_<input_folder>_<runtimestamp>.log` — a new file per invocation (timestamp baked in at `IMSNG_Routine_RASA36.py` ~line 367-388), so one obs date accumulates multiple logs across re-runs; the newest timestamp is the latest run. Format: `%(asctime)s - LEVEL - [file:line] - msg`. `.log.1/.2/.3` rotation files in old runs came from a since-removed `RotatingFileHandler` (10 MB cap) that solve-field output flooded; new runs write a single uncapped `.log`. Watcher/watchdog have their own logs in `log/`.

Multiprocessing note: workers are Linux `fork`ed and inherit the root logger's file handler, so child output lands in the main log (interleaved).

## Known failure signatures

Check this table before deep-diving a log. Grep starters: `grep -n "ERROR\|FINAL FAIL\|Traceback" <log>` and read the run summary at the end of the log.

| Symptom in log | Root cause | Fix / response |
|---|---|---|
| `0/N astrometry succeeded`, mass `ASTROMETRY FINAL FAIL`, `fitstable.c:972` errors | `fitstable.c` errors are a **symptom**: SExtractor found no usable stars, so the xylist retry fails too. Real cause is frame content. **Bright-sky/bad-flat variant:** `Objects: detected 0` on *every* solve across all declinations means calibration (usually a bad own-flat on a high-sky night) wiped the stars — seen 2026-06-22 (median sky 30800 ADU, moon 0.57, 0/427; note 06-23 with a *borrowed* flat solved fine). | Classify the failed frames first: `TRACK_*_D-90` (polar, star-free), `EXPTEST_exp0.01/0.1/0.5s` (too short) are *expected* failures. 60s science frames failing ⇒ real problem (clouds/focus/config/flat). **Total-failure gate (Fix 2a, 2026-07-24):** if `n_astro_ok == 0` and `n_calib_images >= 20`, the pipeline now logs `CRITICAL - ASTROMETRY TOTAL FAILURE`, posts a `:rotating_light:` Slack alert, and `sys.exit(1)` — no more silent clean "COMPLETE" on a 0/N night. The run stays unmarked in the reprocess/watcher state so it re-queues. Partial success (≥1 solved) does not trip it. |
| `FileNotFoundError` in `_subtract_one` / `os.path.getsize(subim)` (~line 1467-1468) | `subtraction_routine2` (hotpants) failed silently, produced no `.com.wcsremap.fits`, then `getsize` crashed | Guard exists now (`os.path.exists` check falls back to `subtraction_routine`); if it reappears, check the reference image in `path_result/TOS/<obj>/*/<filter>/Calib*.com.fits` |
| `TypeError: argument of type 'NoneType' is not iterable` in `calib.py` OBJECT check | FITS header has `OBJECT` key present but blank (None) — seen in ToO folders | Guard `hdr['OBJECT'] is not None` before substring checks |
| SCAMP hangs / `vizier.unistra.fr` timeouts | Unreachable VizieR mirror in `config/` SCAMP `REF_SERVER` | Mirrors already set to cfa.harvard.edu / nao.ac.jp / ast.cam.ac.uk; rotate if one dies |
| SCAMP rejects all sources, "non-zero FLAGS on all sources" | SExtractor flagging every detection (`FLAGS_MASK 0x00f0`, `ASTR_FLAGSMASK 0x00fc` then mask everything) | Investigate SExtractor config producing global flags (saturation level, weight map) |
| PNG previews missing/blank (`save_fits_as_png`) | NaN/Inf pixels (SWarp blank regions) break ZScale; `plt.imsave` not thread-safe under `ThreadPoolExecutor`; MEF with empty HDU 0 | Fixed: finite-mask before ZScale, PIL instead of plt.imsave, HDU-1 fallback. Same pattern applies to any new image-writing code. |
| Only some raw frames calibrated (e.g. 5 of 15), no error | Frames dropped at header-correction/OBJECT-classification stage | Check per-frame header validity (OBJECT, FILTER, EXPTIME present) |
